Ablauf

So funktioniert's

Eine neue oder geänderte Buchung löst per Webhook die Kette aus. Derselbe Weg lässt sich auch manuell im Dashboard anstoßen — etwa für Handwerker oder Reinigung, unabhängig von einer Buchung.

Überblick

Funktionen

✓ Zwei Zutrittssysteme

UniFi Access und/oder Nuki Smart Locks — pro Wohnung oder sogar pro Tür frei kombinierbar, mit identischem PIN auf beiden.

✓ Multi-Wohnung

Bis zu vier Wohnungen, Routing anhand des exakten Smoobu-Property-Namens.

✓ Web-Dashboard

Übersicht aktueller Buchungen und angelegter Besucher direkt in der HA-Seitenleiste, per Ingress abgesichert.

✓ Zeitraum nachträglich änderbar

An-/Abreise eines bereits angelegten Besuchers im Dashboard anpassen — PIN bleibt gleich, nur der Zeitraum wird aktualisiert.

✓ Fehlerbenachrichtigung

Fehlgeschlagene oder dauerhaft unbestätigte PIN-Anlagen lösen eine HA-Benachrichtigung und ein Event aus.

✓ Keine Geheimnisse im Repo

Alle Zugangsdaten werden ausschließlich lokal in der HA-Konfiguration hinterlegt und lokal über HTTPS abgefragt.

Bevor es losgeht

Voraussetzungen

  • ✓UniFi Access: IP/Hostname des Controllers + API-Token (Einstellungen → Sicherheit → Erweiterte API-Einstellungen)
  • ✓Nuki (optional): API-Token aus dem Nuki-Web-Account sowie ein physisches Nuki Keypad am jeweiligen Smart Lock
  • ✓Smoobu: smoobu_api_key und smoobu_api_secret (Einstellungen → API)
  • ✓Webhook-Secret: ein selbst gewählter, ausreichend langer Zufallsstring
  • ✓Exakte Wohnungsnamen in Smoobu: müssen 1:1 in homeN_name eingetragen werden
Setup

Installation

Repository hinzufügen

Einstellungen → Add-ons → Add-on Store → Repositories → github.com/martin141089/smoobu-unifi-autopin-addon

Add-on installieren

„Smoobu UniFi Access AutoPIN" in der Liste suchen und installieren — noch nicht starten.

Konfiguration ausfüllen

Alle Werte aus den Voraussetzungen eintragen. Türgruppen-, Policy- und Nuki-IDs können zunächst leer bleiben.

Add-on starten

Erst danach sind /scan, /policies und /nuki-locks erreichbar.

IDs ermitteln & nachtragen

Türgruppen-, Policy- und Nuki-Smartlock-IDs über die lokalen Hilfsseiten auslesen, eintragen, Add-on neu starten.

Smoobu-Webhook einrichten

Webhook-URL in Smoobu hinterlegen, Events „Buchung erstellt" und „Buchung geändert" aktivieren.

Referenz

Konfiguration

Pro Wohnung frei kombinierbar: nur UniFi, nur Nuki, oder beides gleichzeitig. Bei beiden gleichzeitig erhalten UniFi und Nuki denselben PIN.

config.yaml 
options:
  smoobu_api_key: ""
  smoobu_api_secret: ""          # seit v3.0 — löst den alten Api-Key-Header ab
  unifi_host: ""
  unifi_token: ""
  webhook_secret: ""
  nuki_api_token: ""              # optional, nur falls Nuki genutzt wird
  admin_email: ""                 # optional, Kontaktadresse für UniFi-Visitoren
  default_checkin_time: "15:00"
  default_checkout_time: "11:00"
  notify_on_failure: true          # seit v3.15 — HA-Benachrichtigung bei Fehlern

  homes_count: 1

  home1_name: ""
  home1_policy_id: ""
  home1_door_group_id: ""
  home1_nuki_smartlock_id: ""     # Dezimal- oder Hex-Form akzeptiert

Analog für home2_* bis home4_*. homes_count steuert, wie viele davon aktiv ausgewertet werden.

Dashboard

Erreichbar über Home-Assistant-Ingress — abgesichert mit dem bestehenden HA-Login, kein separates Passwort nötig.

→ Aktuelle & kommende Besucher

Gast, Wohnung, PIN, Zeitraum, genutztes System (UniFi/Nuki) und Quelle. Vergangene Aufenthalte werden automatisch ausgeblendet. Extern in UniFi angelegte Visitoren erscheinen ebenfalls, mit PIN „unbekannt".

→ Zeitraum bearbeiten

An-/Abreise inkl. Uhrzeit nachträglich ändern, PIN bleibt unverändert. Ältere Einträge lassen sich per „Jetzt verknüpfen" einmalig nachrüsten.

→ Kommende Smoobu-Buchungen

Tabelle aller aktuellen und kommenden Reservierungen mit Direktlink „Besucher anlegen", der das Formular vorausfüllt.

→ Manuelle Besucher-Anlage

Komplett unabhängig von einer Buchung — z. B. für Handwerker oder Reinigungspersonal, mit frei wählbarem Zeitraum.

Smoobu

Webhook konfigurieren

http://HOMEASSISTANT-IP:8099/?secret=DEIN_SECRET

Smoobu sendet alle Ereignistypen an diese eine URL — das Add-on filtert intern und reagiert nur auf newReservation und updateReservation. Alle anderen Events werden mit HTTP 200 quittiert und ignoriert.

Platzhalter in Gästenachrichten: Tür-PIN: [doorPin]
